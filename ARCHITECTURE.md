# System Architecture - MobiFin

This document outlines the software design, folder structure, data flow, and role-based boundaries of the MobiFin prototype.

---

## 1. High-Level Design Flow
```
React Frontend (Vite)
         │
         ▼ (CORS, REST API)
FastAPI Backend (Uvicorn Router)
         │
         ├───────────────────────────────┐
         ▼ (SQLAlchemy ORM)              ▼ (Pickle loading)
PostgreSQL / SQLite Database     Offline Model Registry
   - RAW Transaction Logs          - XGBoost Credit Classifier
   - DERIVED Aggregated Metrics    - XGBoost Demand Regressor
   - ML OUTPUT Scores              - Isolation Forest Anomaly
```

## 3. Data Architecture Separation
The database models are divided into distinct layers:
1. **RAW:** Base transactional records (`transactions`, `agents`, `customers`, `loans`).
2. **DERIVED:** Chronological aggregates (`customer_financial_profiles`, `agent_daily_metrics`).
3. **ML OUTPUT:** Artifact estimates generated by inference (`credit_assessments`, `credit_explanations`, `forecasts`, `anomalies`).
4. **RECOMMENDATIONS:** Concrete, deterministic rebalancing scripts (`recommendations`).

---

## 4. SQLite Fallback Mechanics
To ensure out-of-the-box setup:
- The system attempts to connect to the canonical PostgreSQL connection string on startup.
- If the connection fails or triggers a timeout, it logs the exception, initializes an SQLite engine (`backend/mobifin.db`), and toggles an active boolean `sqlite_fallback_active`.
- Sub-routers report this state via `/api/status`, and the React frontend renders a visible badge notifying the operator that SQLite is active.

---

## 5. Security & RBAC Boundaries
Roles are verified server-side on every request using JWT scopes:
- **AGENT:** Has read access to their own transactions, liquidity demand forecasts, rebalancing recommendations, and operational analytics. Cannot access the `/api/credit/assessment` endpoint (locks client profiling summaries to authorized institutional users only).
- **FINANCIAL_INSTITUTION:** Has read access to consenting customer credit profiles, scores, SHAP explanations, and the model performance page. Can search customer IDs.
- **ADMIN:** Full rights, including direct access to **Data Explorer** metrics and the seeding trigger `/api/demo/seed`.
